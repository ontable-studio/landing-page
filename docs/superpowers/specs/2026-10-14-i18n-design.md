# Design: Internationalization (English and Indonesian)

Date: 2026-10-14
Status: Design approved in conversation (three choices below made by the user); built straight from it

## Decisions (made by the user)

| Aspect    | Decision                                                                       |
| --------- | ------------------------------------------------------------------------------ |
| Languages | English (default) and Indonesian                                               |
| URLs      | English at `/`, Indonesian under `/id` (`/id/projects`, `/id/projects/<slug>`) |
| Mechanism | Typed dictionaries of our own, no new dependency                               |

`/design-system` stays English-only and internal.

## Locale and paths (`src/i18n`)

- `Locale` is `"en" | "id"`, `DEFAULT_LOCALE` is `"en"`.
- `localizedPath(locale, path)`: `/projects` becomes `/id/projects`, `/` becomes `/id`, English is unchanged.
- `splitLocale(pathname)`: `/id/projects` gives `{ locale: "id", path: "/projects" }`; `/id` gives `{ locale: "id", path: "/" }`.
- `alternates(path)`: the same page in each language, for `hreflang`.
- `switchPath(pathname, target)`: where the language switcher goes; `undefined` for the design system.
- The locale comes from the URL only. `useLocale()` reads the router location (English outside a router) and `useT()` returns `{ t, locale, to }`, where `to(path)` localizes an internal link.
- No redirect from the browser's language, and nothing stored: each address always shows one language.

## Dictionaries

- Flat keys, `en.ts` is the source; `id.ts` is typed `Record<Key, string>`, so a missing key fails type-check, and a test compares the key sets and rejects empty values and leftover `{placeholders}`.
- `t(locale, key, vars?)` replaces `{name}` placeholders.
- Covers the nav and mobile menu, Home, footer, Projects (title, tabs, empty state, project types), project detail (Back, credit labels, Next project, View larger, status), Lightbox, the whole contact dialog (labels, errors, status, the mail subject), the 404 page.
- The headline lines come from the dictionary. A longer Indonesian line would wrap and break the line masks, so the Home headline scales by `13 / longest line length` (capped at 1) through a CSS variable.

## Project content

- `src/data/projects.ts` stays the English source. `src/data/projects.id.ts` holds, per slug, the Indonesian `summary`, `category`, `status` and gallery alt texts (a draft written from the images, for the team to review).
- `localizeProject(project, locale)` returns the project with those fields and the credit labels (Date, Role, Platform, Made for, Status) translated. Names, platforms, roles and "Game jam" are not translated.
- The `?type=` filter keeps its English slug in both languages; only the labels change.

## SEO per language

- `pageMeta(route, locale)` gives the Indonesian title, description, heading and path; `PageMeta` also lists the `alternates`.
- Each page's head gets `hreflang` links (`en`, `id`, `x-default` pointing at English), `og:locale` (`en_US` / `id_ID`) with the other as `og:locale:alternate`, a canonical per language, and the page's `<html lang>`.
- The build also writes `id/index.html`, `id/projects/index.html` and `id/projects/<slug>/index.html`, with translated head and `<noscript>`. The sitemap lists both languages and each URL carries `xhtml:link` alternates.
- JSON-LD uses the localized URLs and descriptions and `inLanguage`.
- On the client, `useSeo` also updates `<html lang>` and the `hreflang` links, so navigation inside the app stays correct.

## Language switcher

`EN | ID` in the nav and in the mobile menu. Each is a link to the same page in that language, keeping the query string (so the Projects filter survives); the current one has `aria-current` and the right `lang`. Hidden on the design system.

## Out of scope

More languages (the structure allows them), automatic redirects by browser language, translating the design system page, right-to-left layouts.

## Testing

Key parity between dictionaries; the path helpers; `/id` routes render Indonesian text and localized links; the switcher keeps the path and query; project translations are complete; SEO output for both languages (title, canonical, hreflang, `og:locale`, `lang`, sitemap alternates, JSON-LD); the contact validation and mail text in both languages; English output stays as before.
